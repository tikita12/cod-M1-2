# 백엔드 검증 결과

> 이 문서는 2026-10-25의 초기 개발 기록입니다. 이후 실제 배포·Firestore CRUD·캐시·목록 조회 검증을 완료했습니다. 현재 결과와 실제 로그는 [2026-10-27 배포 증빙](deployment_evidence.md)을 참고하세요. 아래의 미검증·설정 전 상태는 당시 상황입니다.

검증일: 2026-10-25

- Python 3.14 가상환경에 로컬 캐시 패키지를 설치했습니다.
- `pip check`: 의존성 충돌 없음.
- 단위/API 테스트: 총 15개 통과.
- CSV 적재 전 검증: 2014-12~2024-12 농산물 14,131건 통과. 클라우드 쓰기 없음.
- 실행 중인 로컬 HTTP 서버의 `/docs`, `/openapi.json`, `/health`, `/api/data/catalog`: 200.
- `/health/ready`, `/api/data/summary?month=11`: Firebase 미설정 상태에서 의도한 503 반환.

API 테스트에서 확인한 것은 테스트 저장소를 사용한 CRUD, 인증, 입력 검증, 중복 방지,
목록 페이징, 변경 후 요약 반영, CORS 및 API 문서입니다.
Firestore SDK 어댑터는 mock으로 중복/누락/접속 실패 변환을 확인했습니다.

실제 Firestore 연결, 실데이터 적재, 클라우드 CRUD, 배포된 URL은 아직 검증하지 않았습니다.
Firebase 프로젝트 ID와 인증 파일 설정 후 연결 검증이 필요합니다.

## 인증 파일 설정 후 확인

- 제공된 서비스 계정 JSON의 형식을 확인하고 로컬 `.env`에 경로·프로젝트 ID를 저장했습니다.
- 관리자 API 키는 무작위로 생성하여 `.env`에 저장했습니다. 비밀값은 출력하지 않았습니다.
- 빈 `FIRESTORE_EMULATOR_HOST`가 잘못된 엔드포인트로 처리되는 문제를 수정했습니다.
- 실제 클라우드 연결 시 Windows 10013(소켓 접근 권한 거부)이 발생했습니다.
- 따라서 실제 Firestore CRUD·CSV 적재는 수행하지 않았습니다.
- 일반 터미널에서 실행할 읽기 전용 `scripts/check_firestore.py`를 추가했습니다.
